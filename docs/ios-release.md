# iOS Release (Xcode Archive)

Chatty Books ships to the App Store the same way treeview does: archive in Xcode
on a Mac with a current Xcode, then upload from the Organizer. `mobile/ios` is
generated by `expo prebuild` and isn't committed, so version and build number
live in `mobile/app.json` (`expo.version`, `expo.ios.buildNumber`).

Bundle ID: `com.chattybooks.app` · Expo SDK 53 · needs **Xcode 16 or newer**
(App Store Connect rejects uploads built with an older SDK).

---

## One-time setup on the build Mac

- [ ] **Xcode** from the Mac App Store. Open it once, accept the licence, and let
      it install the iOS platform.
- [ ] **Xcode → Settings → Accounts → +** → sign in with the Apple ID that's on
      the Chatty Books developer team.
- [ ] **Node 20+** (`node -v`). With Homebrew: `brew install node`.
- [ ] **CocoaPods**: `brew install cocoapods` (`pod --version` to check).
- [ ] **The repo**:
      ```bash
      git clone git@github.com:zahnno/TalkingBook.git
      cd TalkingBook
      npm install          # from the repo root: installs every workspace, applies patches/
      ```
      Don't copy `mobile/.env.local` from another machine. Production values come
      from the committed `mobile/.env.production`.

## Every release

### 1. Update and bump
```bash
cd TalkingBook && git pull && npm install
cd mobile
npm run bump:ios            # build number +1 (skip for the very first upload: it's 1)
npm run bump:ios -- 1.0.1   # new version: also sets the version shown in the store
```
Commit the `app.json` change, so the next release continues from this number.

### 2. Generate the iOS project
```bash
npx expo prebuild -p ios --clean    # also runs pod install
open ios/ChattyBooks.xcworkspace    # the .xcworkspace, not .xcodeproj
```

### 3. Signing (Xcode)
Select the **ChattyBooks** project → **ChattyBooks** target → **Signing & Capabilities**:
- [ ] ✅ **Automatically manage signing**
- [ ] **Team**: the Chatty Books developer team
- [ ] Bundle Identifier shows `com.chattybooks.app`
- [ ] Capabilities list **In-App Purchase** and **Associated Domains**. If In-App
      Purchase is missing: **+ Capability → In-App Purchase**.

The first time, Xcode registers the App ID and creates the Apple Distribution
certificate and App Store provisioning profile for you. Prebuild regenerates
the project, so re-check the Team after every `prebuild --clean`.

### 4. Archive
- Destination (top bar): **Any iOS Device (arm64)**
- **Product → Archive** (5–15 minutes). The Organizer opens when it's done.

### 5. Upload
Organizer → select the archive → **Distribute App → App Store Connect → Upload**
→ keep the defaults (automatic signing, upload symbols) → **Upload**.

The app record must already exist in App Store Connect (Apps → + → New App,
bundle ID `com.chattybooks.app`, SKU `chattybooks-ios`). Processing takes
10–30 minutes, then the build appears under **TestFlight**.

### 6. Test, then submit
- TestFlight → add yourself as an internal tester → install via the TestFlight app.
- Test a subscription with a **Sandbox** Apple ID (Users and Access → Sandbox).
- App Store tab → the version → pick the build under **Build**. The first
  version must include the subscriptions (**In-App Purchases and
  Subscriptions** section) → **Add for Review**.

## Troubleshooting

| Problem | Fix |
|---|---|
| `pod install` fails | `cd ios && pod repo update && pod install`, then reopen the workspace |
| "No profiles for com.chattybooks.app" | Signing tab → re-select the Team; make sure Automatically manage signing is on |
| "Maximum number of certificates" | developer.apple.com → Certificates → revoke an unused Apple Distribution cert (not one another app's releases depend on) |
| Upload: "bundle version must be higher" | `npm run bump:ios`, prebuild again, re-archive |
| Upload: SDK too old | Update Xcode |
| Archive greyed out | Destination is a simulator: choose Any iOS Device |
