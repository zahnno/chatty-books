# Talkingbook Mobile (Expo)

React Native app (iOS, Android, and Solana **Seeker**) for Talkingbook, built with Expo
Router. Shares its API client, auth, hooks, and token logic with the web client via
`@talkingbook/shared`.

Build status (verified): JS bundles for iOS + Android (`expo export`), Android debug and
arm64 release APKs (local Gradle), and an iOS simulator build on EAS
(`--profile ios-simulator`).

The app uses native modules (expo-audio, secure-store, …), so it runs in a **development
build**, not Expo Go. `ios/` and `android/` are generated by `expo prebuild` (CNG) and
are gitignored — never edit them by hand; change `app.json`/plugins instead.

## Prerequisites

- Node 18+, the repo set up as an npm workspace (run `npm install` at the **repo root**).
- Android: Android Studio / SDK + JDK 17.
- iOS: a recent Xcode with an iOS platform installed (App Store submissions need the
  current Xcode). Without one, build iOS in the cloud with EAS (below).

## Setup

```bash
# from the repo root — links @talkingbook/shared into this app
npm install

cd mobile
cp .env.example .env        # then edit EXPO_PUBLIC_SERVER_URI
npm run android             # prebuild + build + install on emulator/device
npm run ios                 # same for iOS simulator (needs local Xcode)
npx expo start              # afterwards: just the dev server for an installed dev build
```

### Server URL (`EXPO_PUBLIC_SERVER_URI`)
The app talks to the existing Node server (default port 5001). Reachability differs by target:
- iOS simulator: `http://localhost:5001`
- Android emulator: `http://10.0.2.2:5001`
- Physical device: your machine's LAN IP, e.g. `http://192.168.1.20:5001`

## What's implemented (Phase 1)

- **Monorepo wiring**: `metro.config.js` watches the repo root and resolves the shared
  package + hoisted deps.
- **API client config**: `lib/api.ts` injects an `expo-secure-store` token store + the
  server URL into `@talkingbook/shared` at startup.
- **Auth gate**: `app/_layout.tsx` redirects between the `(auth)` and `(tabs)` groups
  based on `useAuth()` from the shared package.
- **Auth screens**: login, register, forgot-password, reset-password, verify-email
  (`app/(auth)/`). Email/password is fully wired to `/login`, `/register`,
  `/auth/forgot-password`, `/auth/reset-password`, `/auth/verify-email`.
- **Google Sign-In**: `lib/useGoogleSignIn.ts` via Expo AuthSession → exchanges the ID
  token at `/auth/google/verify`. Button appears only when client IDs are set in `.env`.
- **Tab shell**: Home / Library / Search + a working Settings screen (user, token
  balance, logout).

## What's implemented (Phase 2 — reading core)

- The 50+ React Query data hooks now live in `@talkingbook/shared` (`useBooks`,
  `useUserBooks`, `useBook`, `useBookPages`, etc.) and are reused as-is.
- **Home**: featured / popular / more rows from `useBooks()`.
- **Library**: `useUserBooks()` grid with empty state.
- **Search**: book search against `/books/search`.
- **Book detail** (`app/book/[bookId]/index.tsx`): cover, metadata, description,
  add/remove from library, start/continue reading.
- **Reader** (`app/book/[bookId]/read/[pageNumber].tsx`): vertical scrolling pages
  (`useBookPages`), jumps to the start page, and debounce-saves reading progress to
  `/book/:id/progress` as you scroll.

## What's implemented (Phase 3 — audiobook)

- `context/AudiobookPlayerContext.tsx`: global `expo-audio` player at the app root,
  porting the web logic — per-`(book, profile)` position persistence (AsyncStorage),
  page-timestamp sync (normalized 0–1 → page) that reports progress to
  `/book/:id/progress`, "recent audiobook" memory, and resume from saved position or
  last-read page (whichever is further).
- Background playback + silent-mode via `setAudioModeAsync` (for true lock-screen
  controls in a standalone build, add `expo-audio`'s background audio entitlement).
- `components/AudiobookMiniPlayer.tsx`: persistent mini bar (cover, title, play/pause,
  progress, close) shown above the tab bar; tap opens the full player.
- `app/player.tsx`: full-screen modal with cover, seek slider (`@react-native-community/slider`),
  ±15s, and a voice-profile switcher (`useBookAudioProfiles`).
- Book detail gains a **Listen (audiobook)** button when completed audio profiles exist.

## What's implemented (Phase 4 — character chat)

- `app/book/[bookId]/characters/index.tsx`: character picker (`useBookCharacters`).
- `app/book/[bookId]/characters/[characterId].tsx`: non-streaming chat against
  `/book/:id/character/:cid/chat`. Optimistic user bubble + typing placeholder, then
  refetches page 1 to show the persisted reply and follow-up **suggestion chips**.
  History pagination ("Load earlier messages"). Out-of-tokens errors surface an alert.
- Book detail gains a **Chat with characters** button.

## Subscriptions (in-app purchases)

Paid plans are sold through the **App Store** (iOS) and **Google Play** (Android) with
`react-native-iap`; the web keeps Stripe. The Seeker build (`EXPO_PUBLIC_BILLING_MODE=dappstore`
in `eas.json`) has no Play Billing: it sells 30-day plan passes paid from a Solana wallet
(`lib/solana.ts`, [`docs/seeker-solana.md`](../docs/seeker-solana.md)) and still links to the web.

**Flow:** the store sheet takes payment → the app sends the transaction id / purchase token
to `POST /api/billing/{apple,play}/validate` → the server checks it with Apple / Google,
moves the account onto the plan and grants the plan's tokens → only then does the app finish
the transaction. Renewals, plan changes, cancellations and refunds arrive at
`POST /api/webhooks/{apple,play}`. Token rules match Stripe: the first purchase adds the
plan's tokens; each renewal or plan change resets the balance to the plan's allowance. Every
grant is keyed on the store's transaction/order id (`ProcessedBillingEvent`), so the app and
the webhook can't double-grant.

- `lib/storeBilling.ts`: connect, prices, purchase, restore, manage links. Product ids come from
  the server plan list (`appleProductId` / `playProductId`), not the app.
- `app/subscription.tsx`: store prices, buy / change plan, Restore purchases, Manage
  subscription, renewal terms, Terms / Privacy links. A plan billed elsewhere (Stripe, or the
  other store) can't be bought over, so no one is charged twice. The web likewise refuses to
  change or cancel a store-billed plan.
- `react-native-iap@12.16.4` is patched for Play Billing Library 8
  (`/patches/react-native-iap+12.16.4.patch`, applied by the root `postinstall`), and
  `plugins/withPlayBilling.js` pins Billing 8 in Gradle.

### Store setup (one-time)

**Plans:** run `node scripts/addStoreProductIds.js --dry-run` (from `server/`) and then without
`--dry-run`. This sets `chattybooks_<tier>_monthly` (Apple) and `sub_<tier>` + base plan `monthly`
(Play) on each paid tier.

**App Store Connect** (bundle `com.chattybooks.app`):
1. One subscription group; one auto-renewable 1-month subscription per paid tier with id
   `chattybooks_<tier>_monthly`. Order tiers highest first, so moving up counts as an upgrade.
   Prices must match what the plan promises.
2. Users and Access → Integrations → **In-App Purchase** key → server env
   `APPLE_IAP_KEY_ID`, `APPLE_IAP_ISSUER_ID`, `APPLE_IAP_PRIVATE_KEY_BASE64` (base64 of the .p8),
   `APPLE_IAP_APP_APPLE_ID` (numeric app id). Optional: `APPLE_IAP_BUNDLE_ID`.
3. App Information → App Store Server Notifications → **Version 2**, Production and Sandbox
   URL `https://talkingbook.onrender.com/api/webhooks/apple`.
4. Paid Applications agreement + banking/tax must be active or products won't load.

**Google Play Console** (package `com.chattybooks.app`):
1. One subscription per paid tier, id `sub_<tier>`, with an auto-renewing monthly base plan
   `monthly`. The app has to be uploaded once (any test track) with the billing library
   before subscriptions can be created.
2. Google Cloud: a service account; enable the Android Publisher API; in Play Console →
   Users and permissions, invite the service account with financial-data / manage-orders
   access. Server env `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON_BASE64` (optional `ANDROID_PACKAGE_NAME`).
3. Pub/Sub topic (grant `google-play-developer-notifications@system.gserviceaccount.com`
   Publisher), then a **push** subscription to
   `https://talkingbook.onrender.com/api/webhooks/play` with authentication enabled. Server env
   `GOOGLE_PLAY_PUBSUB_AUDIENCE` (the audience set on the push subscription) and
   `GOOGLE_PLAY_PUBSUB_SA_EMAIL` (its service account). Set the topic in Play Console →
   Monetization setup → Real-time developer notifications, and send a test notification.

Until the server env is set, the validate endpoints return 503 and nothing is charged
without being provisioned (unfinished transactions replay on the next launch).

**Testing:** iOS: a sandbox Apple ID on a device/TestFlight (the server falls back
Production → Sandbox automatically). Android: license testers + internal testing track;
test subscriptions renew every few minutes, which exercises the renewal webhook. Server unit
checks: `node test/storeBilling.test.js`. IAP needs a dev or release build, not Expo Go.

## Deep links (email verification / password reset)

Scheme is `talkingbook` (see `app.json`), with `talkingbook.app` configured for iOS
associated domains / Android app links. Routes:
- `talkingbook://verify-email?token=...` → `app/(auth)/verify-email.tsx`
- `talkingbook://reset-password?token=...` → `app/(auth)/reset-password.tsx`

## Building & shipping (Phase 6)

The project is linked to EAS as `@zahnno/talkingbook` (`extra.eas.projectId` in
`app.json`). `eas.json` profiles (set the real API URLs in each profile's `env`):

| Profile | Output |
| --- | --- |
| `development` | dev client (internal) |
| `ios-simulator` | iOS simulator `.app` — no Apple credentials needed |
| `preview` | internal QA builds |
| `production` | App Store `.ipa` / Play Store `.aab` |
| `seeker` | signed release `.apk` for the Solana dApp Store |

```bash
npm run build:ios        # eas build -p ios --profile production
npm run build:android    # eas build -p android --profile production
npm run build:seeker     # eas build -p android --profile seeker
eas submit --profile production --platform ios   # / --platform android
```

### Seeker (Solana dApp Store)

Seeker is an Android phone, so it runs the same Android build, plus Solana features
behind `IS_SEEKER`: wallet sign-in, the Seeker Genesis Token bonus and crypto plan passes
(see [`docs/seeker-solana.md`](../docs/seeker-solana.md) for server setup). The other
difference is distribution: the Solana dApp Store installs a **signed APK** (not an AAB), and that APK
must be signed with a key that is **separate from your Google Play signing key**.

1. Generate a dedicated keystore once and keep it safe (losing it = no more updates):
   `keytool -genkeypair -v -keystore credentials/seeker.jks -alias talkingbook -keyalg RSA -keysize 2048 -validity 10000`
2. Create `mobile/credentials.json` (gitignored):
   ```json
   { "android": { "keystore": { "keystorePath": "credentials/seeker.jks",
     "keystorePassword": "…", "keyAlias": "talkingbook", "keyPassword": "…" } } }
   ```
3. `npm run build:seeker` (cloud) or `npm run build:seeker:local` → APK. The `seeker`
   profile uses `credentialsSource: "local"`, so it signs with this keystore and not
   the EAS-managed Play key.
4. Copy the APK to `dapp-store/talkingbook-seeker.apk`, add the media referenced in
   `dapp-store/config.yaml` (icon 512², banner 1200×600, ≥4 screenshots), fill in the
   TODOs, then publish with the Solana Mobile CLI (needs a Solana keypair with a little
   SOL for minting the app/release NFTs):
   ```bash
   cd dapp-store
   npx @solana-mobile/dapp-store-cli create publisher -k <keypair.json>   # first time only
   npx @solana-mobile/dapp-store-cli create app       -k <keypair.json>   # first time only
   npx @solana-mobile/dapp-store-cli create release   -k <keypair.json> -b $ANDROID_HOME/build-tools/35.0.0
   npx @solana-mobile/dapp-store-cli publish submit   -k <keypair.json> --requestor-is-authorized --complies-with-solana-dapp-store-policies
   ```

## Branding

App name **Chatty Books**; icon, adaptive icon, and splash live in `assets/images/`
and were generated from the web logos (`client/public/book-logo-light.png`,
`logo-name-light.png`). The splash image keeps the logo + wordmark inside the centre
circle because Android 12+ crops splash icons to a circle. The native splash stays up
until the auth check resolves (`app/_layout.tsx`).

## Known follow-ups

- **`@talkingbook/shared` is plain JS** (no `.d.ts`), so TS sees loose types from it.
  Babel (`babel-preset-expo`) strips types without typechecking, so the app still runs.
- For production Google Sign-In the plan calls for `@react-native-google-signin`
  (requires a dev/standalone build + Google Cloud config). AuthSession is used here so
  the scaffold works without extra native setup.
- The reader renders page text as plain paragraphs; add `react-native-markdown-display`
  if pages use markdown formatting.
- Reader start-page jump uses `scrollToIndex` with variable row heights; for very long
  books consider precomputed layouts or paging if the jump feels imprecise.
